# 0.1 Foundation Inventory

This document classifies the source groups that belong to the current
YuntaoCode 0.1 foundation candidate.

It is not a roadmap. It is a release hygiene inventory used to decide what
should enter the open-source repository and what must remain local-only.

## Include In 0.1 Foundation

### Model Transport Harness

Purpose: keep provider/model transport quirks out of the runner and tool loop.

Source group:

- `runtime/model_harness.py`
- `runtime/tool_call_loop.py`
- `docs/model-harness.md`
- `tests/test_model_harness.py`

Reason to include: model compatibility, visual-input fallback, request-shape
adaptation, and provider-facing facts are foundation concerns. They should not
be scattered through task strategy code.

Purpose: treat running user messages as user-authored semantic updates, not as

### Runtime Advisory Risk Evidence

Purpose: keep runtime warnings as model-facing evidence instead of blockers or
route decisions.

Source group:

- `runtime/agent_strategy/tool_result_risks.py`

- `tests/test_convergence.py`

- `docs/capability-runtime.md`

Reason to include: advisory facts are part of the 0.1 principle that the model
chooses strategy while the runtime records safety, protocol, and evidence
facts.

### Execution Environment And Debug Evidence

Purpose: expose the real command dialect, foreground/background lifecycle,
process state, and verification meaning without adding application-specific
launch routes.

Source group:

- `runtime/skills/shell.py`
- `runtime/debug_session.py`
- `runtime/agent_strategy/classifiers.py`
- `tests/test_shell_tool.py`

Reason to include: direct executable launch, platform shell facts, background
process evidence, and the distinction between process creation and behavioral
verification are cross-platform Capability Runtime contracts. They let the
model choose launch and validation strategy from facts instead of relying on
hidden runtime assumptions.

## Keep Local-Only

These paths are local build output, dependency caches, generated drafts, or
runtime caches. They should not be committed:

- `.venv-sidecar-build/`
- `.pytest_cache/`
- `__pycache__/`
- `desktop-shell/node_modules/`
- `desktop-shell/dist/`
- `desktop-shell/src-tauri/target/`
- `desktop-shell/src-tauri/binaries/local-runtime-*.exe`
- `generated/`
- `promo-video/`
- `ai-plugins/`
- `capability-packs/`

The readiness gate reports known local generated roots so a release candidate
does not accidentally hide large local artifacts.

## Defer From 0.1

No current source group is marked for deferral in this inventory.

Future work should be deferred when it mainly adds a scenario, provider,
marketplace, remote sync, or self-modifying capability without clarifying Task,
Context, Capability, Experience, or release hygiene boundaries.

## Final Review Before Tagging

Before tagging 0.1:

1. Run `python scripts/check_01_readiness.py --strict-js --strict-git`.
2. Confirm ignored local-only paths are either absent or intentionally ignored.
3. Review `git status --short` and stage only the included source groups.
4. Run at least one manual task smoke covering code/file work, one visual or
   preview verification task, and one provider-health task.
